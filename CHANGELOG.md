# Changelog

All notable changes to the **agentic-kb** specification are documented here.

This file follows the [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) convention.
The spec uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html): `MAJOR.MINOR.PATCH`.

## Versioning Conventions

| Bump | When to use |
|------|-------------|
| **PATCH** | Prose edits, typos, clarifications that don't change meaning or structure |
| **MINOR** | New sections, new spec rules, new commands — non-breaking additions |
| **MAJOR** | Breaking changes to the directory layout, command surface, or file formats that invalidate existing implementations |

**Versioning**: the root-level `VERSION` file and this `CHANGELOG.md` track the aggregate framework version. The behavioral spec lives in `plugins/kb/skills/*/SKILL.md` and `plugins/kb/agents/*.md`; the structural reference is `docs/REFERENCE.md`.

## [6.2.0] — 2026-05-24

> **Why MINOR:** this release formalizes the v6.1-era audit closeout work that had already landed in the docs. It adds non-breaking contracts for capture routing, concurrency, promoted-record backlinks, retro closure, HTML artifact lifecycle, marketplace conflict handling, setup first-win behavior, and tracker-backed onboarding while keeping the v6 layer graph and existing command surface compatible.

### Added

- **Reflection-driven capture routing heuristics (#126)** — `capture-routing.md` now defines the operational rubric for reflection-driven routing: strong signals that should propose a non-default contributor-capable layer, weak signals that must fall through to default, concrete strong/weak examples, and a deepest-layer tie-breaker that discloses runner-up matches in the confirmation prompt. `docs/REFERENCE.md`, `kb-management` rule 12, the `/kb` dispatcher, the setup prompt template, and the `kb-operator` capture loop now point at that rubric instead of relying on vague "clearly implies" language. A regression fixture under `tests/fixtures/` captures the strong, weak, and tie-breaker cases for future drift checks.
- **Capture-time layer routing contract** — captures no longer have to land in the private/anchor layer first and propagate upward through `/kb promote`. Three routing modes are now codified: **default** (no target named → active layer), **explicit** (user named a target layer in the invocation, OR a `capture-routing:` rule in `.kb-config/layers.yaml` matches the input source/pattern/workstream → direct write to the named layer with no extra prompt), **reflection-driven** (agent inferred a non-default target from input content/source/context → must **propose** the target, name the reason, and **wait for human confirmation** before mutating; no soft-write to a staging area as a fallback; previous confirmations do not give standing permission). New reference `plugins/kb/skills/kb-management/references/capture-routing.md` carries the full contract, the `capture-routing:` config schema, the response shapes, the interaction with auto-promote (auto-promote stays on the parent edge and never picks non-parent targets), and the audit rule K16 (`capture-routing-unconfirmed`) that flags reflection-driven captures without a paired confirmation entry. `docs/REFERENCE.md` §1 carries the normative subsection. `plugins/kb/skills/kb-management/SKILL.md` adds core rule 12 mirroring the contract and expands the Capture flow row. `plugins/kb/commands/kb.md` and `plugins/kb/skills/kb-setup/templates/kb.prompt.md` expand routing-precedence step 4. `plugins/kb/skills/kb-management/references/command-reference.md` expands the capture row and adds a `/kb <layer> [input]` row for explicit-mode direct routing. `plugins/kb/skills/kb-management/references/promote-contract.md` adds a preamble naming it as the parallel upward-after-maturation flow. `plugins/kb/agents/kb-operator.md` capture loop step 2 and cross-layer flow §5 inherit the contract. `docs/collaboration.md` shared-workspace rule 2a covers the social contract. `docs/glossary.md` adds `Capture routing` as a canonical term and version bumps to 0.9. Closes the spec gap where direct cross-layer capture was implicitly possible (via the "context selects another contributor-capable layer" clause) but never named as a deliberate alternative to the private→shared promote chain, and where the agent had no codified obligation to confirm a self-chosen non-default destination.
- **Concurrency contract (#106)** — new `docs/concurrency.md` defines deterministic resolution for the three concurrency cases the spec previously left ad-hoc: promote collisions resolve via author-id suffix + `_kb-log/promote-conflicts.md` entry; backlink mutation after promote refuses `/kb` writes against `status: promoted` source files and surfaces a diverged-backlink warning at the next `/kb sync` / `/kb audit`; topic merges use the author-sectioned `## Position — @<author> <date>` format so concurrent edits coexist instead of producing raw merge markers. `.kb-log/` and live overviews remain append-only / `merge=ours` per the rules already declared in `docs/REFERENCE.md` §6. Three new audit rules: K13 (`promote-conflict-unresolved`), K14 (`backlink-diverged`), K15 (`topic-author-sections-unconverged`). `docs/collaboration.md` "Failure modes" now points at `concurrency.md` for the parallel-mutation cases. `promote-contract.md` links the new doc.
- **CHANGELOG archive split (#110)** — `CHANGELOG.md` now keeps only `[Unreleased]` plus v5.0.0 and newer (287 lines, down from 588). Pre-v5.0 history moved to `CHANGELOG.archive.md` (v4.1.0 through v0.1.0 initial bootstrap). README footer drops its dedicated changelog block — release history is canonical in `CHANGELOG.md` only.
- **AGENTS Rule 3 — which files have a per-file changelog (#110)** — added an explicit table to `AGENTS.md` Rule 3 listing the file categories that get a per-file `## Changelog` (skill/agent specs, long-lived `docs/*.md`, governance docs) vs the ones that do not (README, templates, generated artifacts, and the inline `## Changelog` lines inside fenced format examples in `docs/REFERENCE.md` §4, which are format spec, not changelogs of the enclosing file). Stops the audit-finding pattern where reviewers grepped `^## Changelog` in `REFERENCE.md` and miscounted format examples as duplicated changelogs.
- **Backlink format for promoted records (#111)** — `docs/REFERENCE.md` §4 now defines a "Backlink (promoted-record stub)" subsection with explicit `status: promoted` + `canonical:` + `promoted-at` (+ optional `promoted-by`) frontmatter and a standardized banner body. `/kb promote` rewrites the source file in place using this format whenever canonical ownership shifts upward. `promote-contract.md` carries the operational rules (path is repo-relative POSIX, evidence moves to the canonical target before the source body is replaced, the operation logs both paths). `/kb audit` rule K11 (`backlink-broken`) detects backlinks whose `canonical:` no longer resolves and offers a rewrite or removal. Migration helpers (`/kb migrate layer-model`, `/kb migrate archives`) rewrite the relative path in the stub when a layer moves, using this format as the canonical anchor. Replaces the previous ad-hoc backlink shape that each agent invented per file.
- **Retro closure lifecycle (#112)** — `docs/REFERENCE.md` §4 retro variant adds `status: open | tracked | closed` frontmatter plus a "Retro closure lifecycle" subsection covering transition triggers (created `open`; `/kb note end` promotes to `tracked` when every *What we will change* item links to a backlog task or decision; `closed` requires evidence of discharged commitments, not their absence), the no-silent-close rule, and supersession when a new retro for the same cadence/workstream lands. `templates/retro.md` writes `status: open` at create. `/kb audit` rule K12 (`retro-status-stale`) reports `open` retros older than 7 days and `tracked` retros eligible for `closed`. `/kb start-week` surfaces unfinished retro commitments. Closes the "retros pile up; commitments evaporate" failure mode the v6.1.0 retro variant left unaddressed.
- **HTML artifact lifecycle (#107)** — `docs/REFERENCE.md` §6 adds "HTML artifact lifecycle (commit, host, merge)" subsection covering default `.gitignore` posture per artifact family (anchor-layer live overviews tracked; non-anchor live overviews ignored; historical and snapshot artifacts always tracked), `.gitattributes` `merge=ours` for committed live overviews (the next regeneration converges deterministically), three hosting modes (`local` / `github-pages` / `external`) selectable in `.kb-config/artifacts.yaml`, and `/kb status --refresh-overviews` as the canonical repair path. `html-artifacts.md` carries the operational pointer and reiterates the determinism requirement that makes `merge=ours` safe. `/kb setup` Q9 now writes the `hosting.mode` choice and the matching `.gitignore` / `.gitattributes` defaults.
- **Marketplace versioning, dependencies, install-mode, priority (#113)** — `docs/REFERENCE.md` §11 adds "Skill versioning, dependencies, and conflict resolution" subsection codifying SemVer per skill (PATCH/MINOR/MAJOR with same rules as the framework), a `dependencies: [{name, version}]` block resolved before install (refuses on unsatisfiable or unresolvable diamond), marketplace-declared `install-mode: open | review-required` (public marketplaces MUST be `review-required`), and `priority:`-based conflict resolution when multiple marketplaces publish the same skill name (higher wins; shadowed skills emit a one-line warning; equal priorities are a config error). Adopters can pin skill versions in `layers.yaml`. `publish-contract.md` ships the publish-side fields, the PR-body requirement (proposed version bump, resolved dependencies, install-mode, shadow list), and the "review-required marketplaces are not done at PR open" reminder. Stops the marketplace from breaking on the first multi-author adoption cycle.
- **Level-1 ritual UX (#108)** — `kb-setup` Step 7d adds an explicit ritual cadence reminder when automation level is `1`: the closing message names `/kb start-day` (morning), `/kb end-day` (before stop), `/kb end-week` (Friday afternoon), and points at `/kb status` as the in-tool nudge channel. Optional `_kb-references/rituals.ics` calendar snippet is offered on opt-in so the user can drop reminders into their calendar. `command-reference.md` triage scan's "Rituals" row makes the level-1 contract explicit (no scheduler at level 1, so the signal becomes an active nudge — *"No `start-day` today. Run `/kb start-day`?"* — rather than a passive observation). At level 2/3 the existing scheduler-ownership reminder fires instead.
- **`kb-setup` Step 7: first-win + next-steps shortlist (#99, #101)** — setup no longer ends with a read-only "Setup: OK" message. After verification, the wizard runs an optional bootstrap capture (default yes, paste URL/file/text → full evaluation gate → finding written → `index.html` regenerated → the artifact path is named back to the user), then emits a curated 3–5 command shortlist tailored to the chosen adoption stage and audience (Stage 1 solo, Stage 1 multi-user, Stage 2 solo, Stage 2 multi-user, Stage 3) plus a short closing summary that names at most 3 next commands. Adopters leave setup with a visible artifact they can open in a browser, not with a flat dump of the full command surface.
- **README "Most used (start here)" section (#101)** — a five-command shortlist (`/kb capture`, `/kb note meeting`, `/kb decide`, `/kb start-day`, `/kb status`) appears above the full Stable core flows list. New readers do not need to learn the full command surface to get value; they can come back to it as their workflow asks for it.
- **`docs/uninstall.md` and `scripts/install.py --uninstall` (#95)** — closes the "rip it out in five" promise. `scripts/install.py --uninstall --target <harness>` removes the harness-side install (`.claude/skills/kb-*`, `.github/prompts/kb.prompt.md`, `.opencode/`, `.agents/skills/kb/`, `.gemini/commands/kb.toml`, `.kiro/skills/kb/`) and never touches the adopter's workspace data. `docs/uninstall.md` documents the full teardown — harness-side, marketplace listing backout per harness, optional workspace-data cleanup, and the roundtrip-reinstall path. README's "Rip it out in five" sentence now links to it.
- **Task ownership rule in REFERENCE.md §10 (#103)** — codifies split ownership between KB tasks and external tracker tickets. KB tasks own knowledge work ("review", "decide", "develop", "draft brief", retro commitments); tracker tickets own engineering work ("implement", "fix", "ship"). They are not two views of the same thing and there is no parallel status reconciliation — read-only links via `connections.product-repos[]` only. Glossary `Task` entry updated. `/kb report status [scope]` is the recommended combined view when both surfaces need to be cited side by side.
- **Auto-promote confidence-threshold algorithm in REFERENCE.md §6 (#105)** — `auto-promote.confidence-threshold` is explicitly the integer evaluation-gate score (0–5); same scale as `docs/REFERENCE.md` §2. Default `4`. Full algorithm spelled out: trigger (scheduled `digest-parent`, not on capture), eligibility filter (score + workstream allow-list + no `manual-review-required` + lifecycle state + multi-user staging rule), promote target (`parent` edge), conflict path (escalate to `_kb-log/exceptions.md`, never silently overwrite). `automation-levels.md` now requires `/kb setup` to confirm threshold + excluded workstreams + a worked-example before writing `level: 3`.
- **Tracker-backed primitive proposal** — added a generic `kb-management` reference for teams that use issue trackers as the operational backbone for decisions, tasks, ideas, feedback, and feature intake while keeping KB files as synthesis, evidence, reports, and backlinks. The pattern carries over native-metadata discipline, explicit routing links, canonical ownership, and confirmation-gated write-back without naming any adopter-specific product or tracker setup.
- **Tracker-backed onboarding contract** — extended setup and reference docs so adopters can choose `files`, `tracker`, or `hybrid` primitive storage per layer. The contract records `primitive-storage` beside tracker connections, covers decisions/tasks/ideas/feature intake/roadmap items, and makes generic GitHub/Jira setup outcomes part of onboarding: type mapping, templates, status/project guidance, guardrail CI, and repo-local tracker workflow skills.
- **GitHub governance profile** — added an adopter-ready GitHub operating-backbone profile: issue forms for feedback, ideas, decisions, tasks, bugs, features, roadmap items, content updates, and governance changes; PR template; path labeler; governance workflow; manual setup checklist for issue types, projects, branch protection, CODEOWNERS, parent/sub-issues, labels, milestones, and required checks; and a repo-local workflow skill that teaches agents the same rules.

## [6.0.0] — 2026-05-10

## [5.0.0] — 2026-04-25

> **Why MAJOR:** the core model is now a flexible layer graph instead of a fixed L1-L5 ladder. This is a breaking semantic change for adopters and tool builders: `.kb-config/layers.yaml` moved to a list-based graph model with `anchor-layer`, `role`, `parent`, per-layer `features`, `marketplace`, and `connections`; note files are now first-class primitives; archive paths are year-based; and setup plus acceptance now prove named-layer promotion/digest flows instead of the old fixed stack.

### Changed

- **Flexible layer graph became the canonical architecture** — `docs/REFERENCE.md`, `docs/glossary.md`, `README.md`, `docs/collaboration.md`, `docs/first-run-acceptance.md`, and the core `kb-management` / `kb-setup` skill specs now describe named layers with `scope`, `role`, `parent`, `features`, `marketplace`, and `connections` instead of numbered L1-L5 slots.
- **Setup and adoption flows now scaffold the 5.0 workspace contract** — `plugins/kb/skills/kb-setup/SKILL.md`, its templates, and the first-run walkthroughs now generate anchor-layer configs, year-based archive paths, note directories, and a deterministic two-layer proof path with explicit cross-layer promote/digest behavior.
- **Cross-layer operations and reports are role-aware** — `/kb promote [file] [layer]`, `/kb digest [layer]`, `/kb digest connections`, `/kb note`, and `/kb report progress [scope]` are now part of the documented stable command surface, with consumer-only layers refusing promote/publish mutations.

- **Acceptance-fixture and index-generator drift against the 5.0 model** — `scripts/scaffold_acceptance_fixture.py`, `scripts/test_acceptance_fixture.py`, `scripts/generate-index.py`, and `scripts/test_generate_index.py` now cover recursive year-based findings, notes, progress reports, and the multi-layer fixture shape used by the new adoption proof.
- **Behavioral and template drift after the major rewrite** — command prompts, instructions, rituals, output examples, roadmap/journey references, and generated scaffold templates were updated so newly installed workspaces match the 5.0 reference docs instead of teaching the retired fixed-ladder model.
